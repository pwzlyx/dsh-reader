# dsh-reader

[GitHub](https://github.com/pwzlyx/dsh-reader) · [npm](https://www.npmjs.com/package/@zengleiyixiao/dsh-reader) · MIT

> npm 包名是 `@zengleiyixiao/dsh-reader`：无 scope 的 `dsh-reader` 已经被另一个 DSH 插件（底部状态栏看小说的那个）先占了，所以挂在自己的 npm scope 下，仓库名保持不变。

在 DeepSeek Harness 的会话里读文件、看结构化文本、比两份文本的小工具。

会话上方多一个「阅读器」页签，里面分 `阅读` / `对比` 两个子页签，干三件事：

- **格式化看得懂**：JSON 缩进 / 键排序 / 压缩成一行、SQL 重排缩进、Markdown 预览（表格、任务列表、代码块都在）
- **正文就是编辑框**：中段直接点进去打字、`⌘/Ctrl + V` 粘贴，`Tab` 缩进两个空格；改完点「格式化」按当前选项重排
- **文本对比**：进来就是左右两张输入框，贴完自动开比；逐行比、改动的词再逐词高亮，支持上下对照和左右并排
- **两个页签都能搜**：阅读和对比共用一条查找栏，命中只算「眼前看得见的行」，折叠区里的不算，所以 `N / N` 指的是你能跳到的数量
- **默认只读**：不碰磁盘；只有你点「保存到文件」才会写回（临时文件 + 原子替换，原权限位保留）
- **切走再切回来不丢**：文件的、粘贴的、对比两边的文本，还有没写回的改动，都按会话留着

## 装

```bash
# 从 npm 装
dsh plugin --profile web add @zengleiyixiao/dsh-reader

# 或者本地开发装（link 到当前目录，改完刷新页面就是新代码）
dsh plugin --profile web add link:/path/to/dsh-reader
```

装完确认 profile 的 `package.json` 里 `dependencies` 有 `@zengleiyixiao/dsh-reader`、`dsh.profile.bundles` 里有 `@zengleiyixiao/dsh-reader`（没有就手动加一行），
然后**重启宿主进程**（`dsh web` 或桌面 App — 宿主是在启动时扫描 bundle 的）。打开一个有内容的会话，上方多出「阅读器」页签就说明成了。

桌面 App 用的是 `desktop` profile，路径是 `~/.dsh/profiles/desktop`；它的 package.json 由 App 独占管理，
命令行 `dsh plugin --profile desktop` 会被拒（"managed exclusively by the Electron application"），
可以直接编辑那份 package.json 加 `"@zengleiyixiao/dsh-reader": "link:/path/to/dsh-reader"` 并在 `dsh.profile.bundles` 末尾加一行，重启 App。

> 排错：插件在浏览器端的模块 id 必须等于包名（`client.js` 里的 `__ModuleLoader__.load({ id: ... })` 要和 `package.json` 的 `name` 一致，
> 挂载声明的 `name` 也要一致）。改包名却没改这两处时，字面上什么都正常，页签就是不出现。

## 用

### 阅读

1. 点「打开文件」→ 弹窗里从 `~`（或当前工作目录）开始点目录，也能按文件名搜（只搜名字，不搜内容）
2. 或者点「粘贴文本」，直接贴一段进来
3. 页签切到「对话」再切回「阅读器」、或者切别的会话再回来，读的东西还在（按会话分开记）
4. 上面那排是格式选项：自动识别 / 强制指定 JSON · Markdown · SQL · 纯文本；JSON 还能选缩进、键排序、压缩成一行；Markdown 可以预览和源码切换

识别规则：先看扩展名（`.json` `.md` `.sql`），没有扩展名就看内容特征（开头 `{` / `[` 且能 parse、有 `select ... from`、有 markdown 标记）。读错了手动掰回来就行；手打进空白页的内容也是按内容特征认的。

### 编辑

中间那块不是图片，是**能直接改的编辑框**：

- 点进去就能写字、删字，`⌘/Ctrl + V` 直接粘贴（不用再走「粘贴文本」弹窗），`Tab` 插两个空格
- 编辑时下面仍然有语法着色、查找命中高亮、行号，光标在哪行一目了然
- 手打的内容**不会**自动重排——想排版点那排选项里的「格式化」（JSON 按当前缩进 / 键排序 / 压缩选项重排，SQL 按子句重排）
- 改过之后上方出现「内容改过了，还没写回文件」：**保存到文件**写回磁盘（原子替换），**撤销修改**回到打开时的内容
- 保存写的是**眼前这段文本**：文件原本没排版的话，保存后就是排版过的样子；想保留原样，先把「格式化排版 / 格式化」关掉

切到「对比」默认就是**左右两张输入框**：把两段文本分别粘进去（`⌘/Ctrl + V`），或者各点一次「打开」挑文件，两边都有内容就自动进入对比。中间那排是看法：

- **并排编辑**：两边变回可编辑的输入框，一边改一边看差异（改完切回来重新比）

- **上下对照（unified）**：`@@ 左 N 行 / 右 M 行` 分段，`-` 是左边有、`+` 是右边有
- **左右并排（side）**：一行一行对齐，两边各带行号
- **忽略空白差异**：只差空格 / 缩进 / 行尾空格的，不算差异
- **上下文**：差异前后各留几行（1 / 3 / 6 / 10）
- 两种视图里被折叠的相同行都会显示成 `⋯ 上面/中间/下面还有 N 行相同的内容`，点一下就多展开几行（每次 +6，最多 40）

行级差异定位之后，成对的改动还会做词级比对，红色是删掉的字，绿色是新加的字。左右两边都能点「打开」各挑一份文件，或者直接粘；「互换」交换两边，「清空」重来。

对比里也有「查找」：黄色是全部命中，深色是当前那处，右边写着 `2 / 5 · 左 · 第 57 行`（统一视图里只写 `第 N 行`），按 `Enter` / `F3` 一个个跳；折叠起来的相同行不算命中，不会跳到一个你看不见的位置。

### 查找与替换

阅读页右上角有「查找」（对比页也有），或者直接 `Cmd/Ctrl + F`，正文上方弹出一条查找栏：

- 边打字边高亮，所有命中是黄色，当前那一处是深色，右边显示 `1 / N`（对比页会带上「左 · / 右 ·」，说明这处在哪边）
- `Enter` / `F3` 下一个、`Shift + Enter` 上一个，到头会绕回开头；`Esc` 关掉查找栏
- 对比页只按「看得见的行」计数：折叠起来的相同行里的命中不算，也不会把你滚到一个看不见的位置
- 两个开关：**区分大小写**、**正则**（正则写错会直接把错误提示出来，不会悄悄搜不到）
- **替换**换当前这一处，**全部替换**一次换完，提示「替换了 N 处」；正则替换支持 `$1` 这种分组引用
- 换完正文就变了，但**没落盘**：上方出现「内容改过了，还没写回文件」，点**保存到文件**才写回，或者点**撤销修改**变回原样
- 粘贴进来的文本没有对应文件，只能「复制」走

保存写的是**当前显示的内容**：开着「格式化排版」保存，写回去的就是格式化后的文本；想保留原样，先把「格式化排版」关掉再保存。

### 快捷键

- `1` 切到「阅读」，`2` 切到「对比」（输入框里打字时不会触发）
- `Cmd/Ctrl + F` 打开查找，`Esc` 关闭；`Enter` / `F3` 下一个、`Shift + Enter` 上一个
- 对比页里 `Cmd/Ctrl + G` 下一个、`+ Shift` 上一个
- 编辑框里：`Tab` 插两个空格，`⌘/Ctrl + V` 直接粘贴，`⌘/Ctrl + Z` 走浏览器原生撤销
- 「复制」会把当前看到的内容（格式化之后的结果）写进剪贴板，点完立刻变「已复制」

## 它读哪里

文件读取走宿主半端注册的只读路由 `/api/dsh-reader/*`：

| 路由 | 作用 |
| --- | --- |
| `GET /api/dsh-reader/info` | 当前工作目录、家目录、路径分隔符 |
| `GET /api/dsh-reader/list?path=` | 列目录（目录在前，带大小、修改时间、扩展名） |
| `GET /api/dsh-reader/read?path=&max=` | 读文本（默认 4MB，最多 32MB；二进制靠 NUL 字节嗅探识别后拒读） |
| `GET /api/dsh-reader/search?path=&q=&limit=` | 按文件名子串搜索（深度 6，跳过 node_modules/.git/dist/target 之类） |
| `POST /api/dsh-reader/write` | 保存文本（只在点「保存到文件」时调用；先写同目录临时文件再 `rename` 原子替换，沿用原文件权限位） |

唯一的写入口是 `POST /write`，必须由界面上的「保存到文件」显式触发；插件启动、读文件、对比都不会写盘。

## 实现

- `index.js` —— 宿主半端：只依赖 node 内置模块，注册上面那几条路由
- `client.js` —— 浏览器半端：自注册脚本（`window.__ModuleLoader__.load`），往 `conversation.view` 槽位注册 `reader` 页
- `cordis.patch.yml` —— bundle 挂载声明

浏览器半端只用宿主给的 `react`，其余全是手写纯函数，没有第三方依赖：

- JSON 格式化 + 错误定位（哪一行哪一列）+ 逐行 token 高亮
- SQL 格式化（子句换行、缩进栈、JOIN ... ON、CASE、子查询）+ token 高亮
- 小号 Markdown 解析器（标题、段落、列表、任务列表、表格对齐、引用、围栏代码、行内强调/链接/行内代码）
- Myers diff（行级 + 词级），统一视图 / 并排视图，上下文折叠
- 查找/替换：按行切 span 做命中定位（命中片段套在语法着色里，颜色不丢），大小写/正则、`$1` 分组替换、替换后脏标记与撤销
- 编辑框（`EditableCode`）：下层是着色好的 `<pre>`，上层是文字透明的 `<textarea>`，两层同字体 / 同行高 / 同内边距；滚动时把下层的 `transform` 跟着挪，所以滚动条、光标、选区都还是浏览器原生的

## 已知边界

- 单个文件超过 4MB 只读前面一段（弹条提示）；超过 4000 行（或 400KB）关掉语法着色和行号，只留纯文本编辑框，免得卡
- 开了「自动换行」行号会隐藏：一行可能折成好几行，行号会对不上
- 编辑框是「高亮层 + 透明 textarea」两层叠出来的，不是 CodeMirror：没有多光标、没有自动补全、没有语法校验（JSON 只在格式化时报错定位）
- SQL 格式化是「排得整齐」级别的，不是完整 parser：极端方言语法（存储过程、复杂 DDL）可能排得不够漂亮，但不会改坏原文（`格式化排版` 关掉就是原文）
- 二进制文件不读，只提示
- 保存回写的是「当前显示的内容」，不是原文（见上面「查找与替换」最后一段）；超过 32MB 的文件拒绝写入
- 「切走再回来还在」只在当前页面生效：整页刷新（F5）之后要重新打开文件
